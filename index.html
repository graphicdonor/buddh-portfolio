01 / Problem

Construction workflows are deeply fragmented

Teams ran critical workflows across Excel for BOQs, WhatsApp for communication, ERPs for finance, and manual on-site reporting — resulting in zero real-time visibility, delayed decisions, heavy cost leakages, and crushing operational overhead.

📊
Excel BOQs & manual data
Bill of quantities managed in spreadsheets with no live pricing, no vendor linking, and no audit trail — leading to costly errors.
💬
WhatsApp-driven communication
Critical project decisions buried in chat threads with no structure, no accountability, and no searchable history.
🔍
Zero real-time visibility
Stakeholders had no live view of project health — everything was reactive, never proactive, driven by delayed manual reports.
💸
High cost leakages
Disconnected billing, payment, and reconciliation caused cash leakages, invoice disputes, and follow-up loops that cost weeks.

04 / UX Strategy

AI-first, systems-led design

The UX strategy was built around four principles that governed every design decision across the platform — from onboarding to AI Copilot to offline execution.

AI-First Interaction
Designed every surface to leverage AI — natural language queries, predictive suggestions, and automated workflows as the default, not a feature.
Progressive Disclosure
Construction data is dense. Applied strict hierarchy and contextual reveal — showing complexity only when the user is ready for it, not all at once.
Role-Based UX
Each stakeholder — developer, contractor, site manager — gets a tailored view of the same underlying data, reducing noise and increasing task completion.
Mobile + Offline First
Designed for the construction site, not the boardroom. Every flow works on mobile and degrades gracefully to full offline capability when network fails.

01 / Problem

Most gym-goers plateau because programming is hard

People track workouts in notes apps, forget last session's weights, or follow generic plans that never adapt. Dedicated fitness apps are either too expensive, too complicated, or disconnected from real programming logic.

📈
No automatic progression
Users have to decide when to increase weight — a decision that requires programming knowledge most people don't have.
🗂️
Fragmented tracking
Separate apps for strength, cardio, and body stats — no single platform unifying the full fitness picture.
📶
No offline support
Most fitness apps fail in gym environments with poor Wi-Fi — the exact moment you need them most.
🎚️
Generic programs
One-size-fits-all plans with no beginner/advanced differentiation — and no adaptation over the 60-day arc.
02 / Key Features

Ten features, one cohesive system

Every feature was built around the core premise: remove every decision that isn't "show up and lift." The app handles programming, progression, tracking, and motivation automatically.

⚙️
Linear Progression Engine
Auto-adjusts weights: +2.5kg upper / +5kg lower on success, holds on miss, 5% deload after two failures. Zero programming knowledge required.
🏋️
5 Structured Programs
PPL, 6-Day Bodybuilding, 3-Day Full Body, 4-Day Intermediate, and 5-Day Hypertrophy — across 4 progressive phases spanning 60 days.
⚡
Beginner / Advanced Toggle
A single switch adjusts sets, reps, and rest periods across every exercise in every program in real time — no separate app versions needed.
🎯
Strength Goal Plans
Set a custom goal (e.g. Bench 80kg → 100kg in 12 weeks). The app auto-generates a week-by-week plan and tracks you against the curve on a live chart.
🗺️
Live GPS Athletics Tracker
MapLibre GL + CartoDB tiles for zero API cost. Real-time route polyline, Haversine distance, 30s rolling pace window with On Track / Speed Up / Ease Up status.
👁️
Admin CRM
Role-gated panel (React 19 + Tailwind v4) with KPI dashboard, searchable user list, per-user session history, and role management.

03 / Architecture

Three independent apps, one monorepo

The system is structured as a monorepo with three independent apps — user PWA/APK, admin CRM, and Express REST API — each with their own stack, deployed as a unified platform on Netlify.

/src — User PWA + Android
React 18 · Vite 5 · Tailwind v3 · Capacitor v8. Shipped as both a PWA with Workbox service worker and a native Android APK with haptics, local notifications, and GPS access.
/admin-app — Admin CRM
React 19 · Vite 8 · Tailwind v4. Intentionally runs a newer stack — served as a testbed for the newer ecosystem before migrating the main app.
/backend — REST API
Express + Prisma v5 + PostgreSQL (Supabase). Entire Express app bundled by esbuild into a single Netlify Function via serverless-http — zero server management.
Dual-Layer Persistence
Every write hits localStorage immediately for instant UI, then syncs to backend async. On mount, server state reconciles. App is fully functional offline — critical in gym environments with poor signal.
04 / Engineering Challenges

Five real problems, five precise solutions

Problem
Rest timer invisible behind nav bar
backdrop-filter on the nav created a new stacking context in WebKit/Blink — making any z-index on children irrelevant. The overlay rendered underneath regardless of the value set.
Solution
Rendered the rest timer into a React Portal targeting #portal-root — a sibling div placed after #root in index.html. Portals escape the component tree entirely, rendering above any stacking context in the app.
Problem
Full Express + Prisma backend with zero server management
One function per route would duplicate middleware across dozens of handlers. A dedicated server meant infrastructure overhead for a solo side project.
Solution
Wrapped the entire Express app with serverless-http as a single Netlify Function. esbuild bundles at deploy time with @prisma/client marked external — keeping cold starts low while retaining a full ORM and structured routing.
Problem
Native feel on a web app — tap delays, zoom, scrollbars
PWAs often feel "webby" — 300ms tap delays, iOS auto-zoom on inputs, grey tap highlights, rubber-band interference, visible text selection on press.
Solution
Comprehensive fix layer: touch-action: manipulation kills the 300ms delay, font-size: 16px on all inputs blocks iOS zoom, overscroll-behavior: none stops pull-to-refresh interference, active:scale-[0.96] on every button gives tactile press feedback. Capacitor haptics fire on every button click via the base component.
Problem
GPS maps without a billing API key
Google Maps and Mapbox both require accounts with billing. For a zero-cost infrastructure target, this was a hard blocker from the start.
Solution
Switched to MapLibre GL v5 (Apache 2.0) with CartoDB Dark Matter raster tiles — fully free, no API key, no rate limits for standard usage. The dark tile theme matches the app's aesthetic perfectly with no extra configuration.
