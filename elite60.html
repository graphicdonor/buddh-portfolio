01 / Problem

Most gym-goers plateau because programming is hard

People track workouts in notes apps, forget last session's weights, or follow generic plans that never adapt. Dedicated fitness apps are either too expensive, too complicated, or disconnected from real programming logic.

📈
No Automatic Progression
Users must decide when to increase weight — requires programming knowledge most beginners don't have. Without automation, plateaus are inevitable.
🗂️
Fragmented Tracking
Separate apps for strength, cardio, and body stats create friction. No single source of truth means data is always incomplete or stale.
📶
No Offline Support
Most fitness apps fail in poor Wi-Fi gym environments. If the network drops, you lose your workout history and have to start over.
🎚️
Generic Programs
One-size-fits-all plans with no beginner/advanced differentiation. Most programs ignore individual capacity, leading to either under-training or injury.
02 / Key Features

Ten features, one cohesive system

Every feature was built around one premise: remove every decision that isn't "show up and lift." The app handles programming, progression, tracking, and motivation automatically.

⚙️
Linear Progression Engine
+2.5kg upper / +5kg lower on success. Holds on miss. 5% deload after two consecutive failures. Zero manual input required from the user.
🏋️
5 Structured Programs
PPL, 6-Day Bodybuilding, 3-Day Full Body, 4-Day Intermediate, 5-Day Hypertrophy — across 4 phases in 60 days. Each phase auto-advances.
⚡
Beginner / Advanced Toggle
Adjusts sets, reps, and rest periods in real time across all programs. One switch changes the entire workout structure without rebuilding the plan.
🎯
Strength Goal Plans
Set a goal (e.g. Bench 80kg → 100kg) and get an auto-generated weekly plan with a live progress chart tracking your path to the target.
🗺️
Live GPS Athletics Tracker
MapLibre GL + CartoDB raster tiles. Real-time route polyline, Haversine distance calculation, 30-second rolling pace with live status. Zero API cost.
👁️
Admin CRM
KPI dashboard, searchable user table, per-user session history, and role management. Built with React 19 + Tailwind v4 as a separate testbed app.

03 / Architecture

Three independent apps, one monorepo

Structured as a monorepo with three independent apps — user PWA/APK, admin CRM, and Express REST API — each with their own stack, deployed as a unified platform on Netlify.

/src — User PWA + Android
React 18, Vite 5, Tailwind v3, Capacitor v8. Ships as a progressive web app via Workbox service worker and as a native Android APK from the same codebase.
/admin-app — Admin CRM
React 19, Vite 8, Tailwind v4. Built as a separate internal app — deliberately on newer ecosystem versions to serve as a testbed for upcoming migrations.
/backend — REST API
Express + Prisma v5 + PostgreSQL on Supabase. Bundled by esbuild into a single Netlify Function via serverless-http — zero server management.
Dual-Layer Persistence
Every write hits localStorage immediately, then syncs async. Server state reconciles on mount. Fully functional offline — gym environments have poor connectivity.
04 / Engineering Challenges

Five real problems, five precise solutions

Problem
Rest timer rendered invisible behind the navigation bar — z-index stacking context made it impossible to overlay correctly across different views.
Solution
Used React Portal targeting a #portal-root sibling div to escape the stacking context entirely. Timer renders at document root level, always visible.
Problem
Running a full Express + Prisma backend with zero server management — traditional serverless functions can't bundle Prisma's native binary dependencies cleanly.
Solution
Wrapped the entire Express app with serverless-http. esbuild bundles everything with Prisma marked external, letting Netlify handle the native binary layer.
Problem
Making a web app feel truly native — 300ms tap delays, iOS auto-zoom on inputs, grey tap highlights, rubber-band interference, and visible text selection on press.
Solution
touch-action: manipulation, font-size: 16px on inputs, overscroll-behavior: none, active:scale-[0.96] on buttons, and Capacitor haptics for native feedback.
Problem
GPS workout maps needed real-time routing and tile rendering but any commercial map provider (Mapbox, Google Maps) would incur API costs at scale.
Solution
Switched to MapLibre GL v5 (Apache 2.0) with CartoDB Dark Matter raster tiles — fully free, no API key, no rate limits, matches the app's dark aesthetic perfectly.
